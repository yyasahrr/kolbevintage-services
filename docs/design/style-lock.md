# Style Lock — کلبه وینتیج

> این فایل «قفل سبک» پروژه است. پس از این نقطه، هیچ صفحه‌ای اجازهٔ اختراع توکن جدید ندارد.
> هر مقدار اینجا **قطعی** است و بر اساس پاسخ‌های شما به پرسش‌نامهٔ `100-questions.md` انتخاب شده.
> تاریخ قفل: ۱۴۰۵/۰۷/۰۶ — مرجع: رسیپی «کرِم و بلوط» (اسکیل `clean-minimal-beige-light-mode`)

---

## ۱. جهت هنری (Design Read)

```yaml
artifact: فروشگاه اینترنتی + پنل‌های عملیاتی (ادمین، VIP، عمده، تأمین‌کننده)
audience: مشتری بوتیک وینتیج (موبایل‌اول) + تیم عملیات کلبه
visual-language: کرِم و بلوط — بژ گرم لایه‌ای، چوب روشن، پاستل‌های میوه‌ای به‌عنوان سیگنال
mode: overhaul (بازطراحی کامل، بر پایهٔ حفظ همهٔ قابلیت‌ها)
visual-variance: 6
motion-intensity: 7          # پاسخ سؤال ۵۱ — سینمایی در ویترین، مهارشده در پنل‌ها
information-density: 5.5     # پاسخ سؤال ۷۶ — فروشگاه ۴، پنل‌ها ۶
asset-dependence: 8          # تصویر واقعی/تولیدشدهٔ اختصاصی، نه سیلوئت CSS
brand-fidelity: 5            # سرمهٔ قدیم حذف می‌شود؛ هویت جدید بر پایهٔ پالت کرِم
```

**تصمیم‌های مبنایی:** سرمهٔ `#011c3a` کاملاً حذف می‌شود · هیچ متن لاتین در UI عمومی نیست
(جزئیات در بخش ۷) · اعداد فارسی · RTL کامل.

**قرارداد رنگ (قفل‌شده):**
- متن‌های مجاز روی کرِم: `text`، `text-muted`، `primary`، `accent`، هر چهار رنگ وضعیت (همه ≥ ۴.۵).
- دکمه: پس‌زمینهٔ `primary` + متن `on-primary`؛ دکمهٔ ثانویه: پس‌زمینهٔ `accent` + متن `on-accent`.
- `border` فقط خط مویی است و **نباید تنها حامل معنا باشد** (کنتراست ۱.۴۵). هر وضعیتی که باید فهمیده شود، با رنگ وضعیت یا آیکون بیان می‌شود.
- هیچ رنگ خارج از این جدول در UI مجاز نیست.
- پاستل‌ها (زرد/سالوی/مرجانی/صورتی/آبی) فقط در **دکمهٔ ثانویه، حالت hover و چیپ** (پاسخ ۱۰) و همیشه از نسخهٔ کنتراست‌تأییدشدهٔ همان خانواده.

## ۳. تایپوگرافی

- **متن:** وزیرمتن (متغیر، محلی) — وزن‌های ۴۰۰/۵۰۰/۷۰۰.
- **نمایش (تیتر):** استداد (Estedad Variable، OFL) — برای تیترهای ≥ ۲۴px استفاده می‌شود (پاسخ ۱۹ = ترکیب دو فونت).
- **هیچ متن لاتین در UI عمومی نیست** (پاسخ تأییدی)، پس هر دو فونت باید پوشش فارسی کامل داشته باشند.
- **اعداد همه فارسی** (پاسخ ۲۵) — از تبدیل ارقام با `Intl.NumberFormat("fa-IR")`؛ اعداد داخل کد محصول/شناسه لاتین می‌مانند (داده، نه UI).
- **مقیاس سیال** (پاسخ ۲۳) و **تنظیم موبایل با تست سه‌عرضی** (پاسخ ۲۷):

| نقش | اندازه (clamp) | ارتفاع خط | وزن |
|---|---|---|---|
| `display-xl` (هیرو) | `clamp(2.25rem, 6vw, 4.25rem)` | ۱.۰۸ | ۷۰۰ |
| `display-lg` | `clamp(1.75rem, 4vw, 2.75rem)` | ۱.۱۵ | ۷۰۰ |
| `title` | `clamp(1.25rem, 2.4vw, 1.75rem)` | ۱.۳ | ۵۰۰ |
| `body` | `clamp(0.9375rem, 1.05vw, 1.0625rem)` | ۱.۸ | ۴۰۰ |
| `body-sm` | `0.875rem` | ۱.۷۵ | ۴۰۰ |
| `label` (ریز-تیتر فارسی) | `0.75rem` + `letter-spacing: .04em` | ۱.۶ | ۵۰۰ |

قواعد: `text-wrap: balance` برای تیترها و `pretty` برای پاراگراف‌ها؛ حداکثر عرض متن ۶۸ch؛
هیچ `letter-spacing` باز روی متن فارسی (اتصال حروف را می‌شکند) — فقط روی برچسب‌های کوچک فارسی با احتیاط.

## ۴. فاصله، شعاع، سایه

- **مقیاس فاصله:** `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128 / 192` (px).
- **ریتم عمودی بخش‌ها** (پاسخ ۳۴): بخش شاخص `128–192`، بخش معمولی `96`، بخش پیوسته `64`.
- **قاعدهٔ ضد-فشردگی:** فاصلهٔ داخلی کارت ≤ فاصلهٔ بین کارت‌ها؛ حداقل پدینگ کارت ۲۴px.
- **شعاع** (پاسخ ۱۳ = گرد): کنترل `14px`، کارت `20px`، شیت/مودال `24px`، چیپ `999px`، تصویر داخل کارت `14px`.
- **سایه** (پاسخ ۱۴ = متوسط):
  - `--kv-shadow-card: 0 2px 6px rgba(26,23,20,.05), 0 12px 28px rgba(26,23,20,.07)`
  - `--kv-shadow-overlay: 0 18px 50px rgba(26,23,20,.18)`
  - در تاریک: سایه‌ها کم‌رنگ و با بوردر جایگزین می‌شوند.

## ۵. حرکت (پاسخ ۵۱ = ۷–۸ سینمایی، ۵۳ = بدون تکرار، ۵۷ = کاهش‌حرکت اجباری)

| موقعیت | مشخصات |
|---|---|
| ورود بخش‌ها (فقط یک‌بار) | `opacity 0→1` + `translateY(24px→0)`، ۲۴۰–۴۸۰ms، `cubic-bezier(.22,.61,.36,1)` |
| هیرو سینمایی | پارالاکس اسکرول‌محور (مقیاس/جابه‌جایی تصویر تا ۸٪)، بدون قفل اسکرول |
| hover کارت محصول | تصویر تا `scale(1.03)`، ۳۲۰ms، فقط روی دستگاه‌های `(hover: hover)` |
| درایو سبد / مودال | ورود ۲۲۰ms `ease-out`، خروج ۱۶۰ms `ease-in`، `transform/opacity` |
| شیت موبایل | ۲۶۰ms با کشیدن‌پذیری و بستن با سوایپ |
| ریزحرکت‌ها | تغییر دکمه ۱۴۰ms، چیپ فیلتر ۱۶۰ms، تیکر قیمت (توقف در `focus`) |

- اسکرول نرم با احتیاط (پاسخ ۵۵): فقط دسکتاپ با `(pointer: fine)` و بدون قفل.
- **ممنوع:** `transition: all` · `ease-in` در ورود UI · `scale(0)` · انیمیت `width/height/top/left` · لوپ بی‌نهایت تزئینی.
- انیمیشن ورودی هر بخش **فقط یک‌بار** در هر نشست (پاسخ ۵۳).
- `prefers-reduced-motion: reduce` → همهٔ حرکت‌ها به ≤ ۱ms، حذف پارالاکس و اسکرول نرم (اجباری — پاسخ ۵۷).

## ۶. کامپوننت‌ها (قطعیت‌یافته)

| کامپوننت | مشخصات |
|---|---|
| کارت محصول | تصویر **مربع** (پاسخ ۴۲)، کارت قاب‌دار `surface` + `border`، مشخصات کوتاه (جنس/سایز)، برچسب کوچک شیشه‌ای روی تصویر (پاسخ ۴۳) |
| دکمهٔ اصلی | `primary` تیره‌ی گرم + سایهٔ داخلی نرم (`inset 0 1px 0 rgba(255,255,255,.14)`) + شعاع ۱۴px (پاسخ ۴۴) |
| دکمهٔ ثانویه | شبح‌وار با بوردر ۱px و متن `accent`؛ در hover فیل پاستلی ملایم |
| ورودی | بوردر نازک + پس‌زمینهٔ `surface`، برچسب شناور ندارد؛ فوکوس = حلقهٔ ۲px `--kv-focus` + تغییر بوردر (پاسخ ۴۵) |
| مودال | شعاع ۲۴px، در موبایل **شیت پایین‌کشیدنی** (پاسخ ۴۶) |
| جدول | دسکتاپ: خطوط نازک افقی بدون راه‌راه؛ موبایل: کارت‌محور با جزئیات بازشدنی (پاسخ ۴۷) |
| نمودار | ساده و داده‌محور: بدون گرید اضافه، بدون افکت؛ رنگ‌های سری از پالت مشتق می‌شوند (پاسخ ۴۸) |
| توست/اعلان | یک سیستم واحد در کل پلتفرم، متن فارسی، آیکون متناسب با وضعیت (پاسخ ۸۵) |
| حالت خالی/بارگذاری/خطا | اسکلتون تصویری + پیام فارسی + کنش بعدی مشخص — برای همهٔ سطوح داده‌ای (پاسخ ۶۹) |
| صفحهٔ خطا | `PortalErrorBoundary` در همهٔ پنل‌ها: پیام فارسی + دکمهٔ «بارگذاری مجدد» (پاسخ ۷۹) |

## ۷. ساختار و چیدمان

- **گرید قاب‌دار ماژولار** (پاسخ ۳۱) با شِل قاب در بخش‌های شاخص (پاسخ ۳۲).
- عرض محتوا **بر حسب نوع صفحه** (پاسخ ۳۳): فروشگاه و لیست‌ها `1320px`، صفحهٔ محصول/ادیتوریال `1140px`، پنل‌ها `1440px` سیال.
- هدر: شفاف روی هیرو → چسبانِ مات با بلور ملایم بعد از ۶۴px اسکرول (پاسخ ۳۵).
- مگامنو بازطراحی‌شده با تصویر دسته (پاسخ ۳۶).
- سبد: **درایو + صفحهٔ کامل** (پاسخ ۳۹).
- فوتر: مینیمال تک‌ردیفه با خبرنامه کوچک (پاسخ ۴۰).
- موبایل: نوار پایین کامل (خانه/دسته‌ها/جست‌وجو/سبد/حساب — پاسخ ۶۱)، محصولات دوتایی (پاسخ ۶۲)، جدول‌ها کارت‌محور (پاسخ ۶۳).
- پنل‌ها: سایدبار **قابل جمع‌شدن به آیکون** (پاسخ ۷۷) با پالت هم‌خانوادهٔ فروشگاه (پاسخ ۷۸)، چگالی ۶.

## ۸. بک‌اند و قراردادها

- همهٔ UI به endpointهای موجود (`/store/kolbe/*`) وصل است؛ **هیچ دادهٔ جعلی در فرانت** (پاسخ ۸۷).
- نبود داده → حالت «به‌زودی»/خالی، نه ارور (پاسخ ۷۳).
- دیتابیس محلی: embedded postgres → migrate → seed سبک و واقع‌گرایانه (پاسخ ۸۸، ۸۹).
- منطق پول/سفارش دست‌نخورده؛ تغییر فقط ظاهر + پیام‌های خطا (پاسخ ۹۰).
- لایهٔ تم/بلوک (پاسخ ۵۰ + تکمیلی): مدیریت تم، رنگ، تایپ، هدر/فوتر و بلوک‌های صفحه از پنل، با بک‌اند و نسخه‌بندی — صفحه‌ساز کاملِ کشیدنی در فاز بعد.

## ۹. قواعد تحویل

- تست مرورگری همهٔ صفحه‌ها + گزارش خطای کنسول/شبکه + `typecheck` و `test` و `build` سبز (پاسخ ۸۶).
- اگر تضاد پیش آمد: **زیبایی مقدم است، ولی تست‌ها با توضیح به‌روز می‌شوند** (پاسخ ۹۱).
- در پایان: یکدستی همه‌جا مهم‌تر از عمق یک صفحه (پاسخ ۹۳) — ترتیب کار: Style Lock → صفحهٔ اصلی → فروشگاه → پنل‌ها.
- مستندات: همین فایل + `docs/design/change-log.md` + اسکرین‌شات (پاسخ ۹۹).

## ۱۰. قفل سبک روی دادهٔ ذخیره‌شده (باتش ۷)

حذف رنگ ممنوعه از کد کافی نیست؛ تنظیمات ظاهر در `localStorage` مرورگر و در `site_setting` سرور
ذخیره می‌شود و مقدارهای قدیمی را با خود حمل می‌کند. `storefront/lib/styleLock.ts` هر رشتهٔ رنگی را در
هر عمق درخت تنظیمات جایگزین می‌کند (`#011c3a`, `#071c31`, `#17253b`, `#22304a`, `rgba(1,28,58,…)`, …) →
پس سرمه‌ای نه در کد می‌ماند، نه در داده.
