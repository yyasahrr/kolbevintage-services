# ADR-002: لایه یکپارچه Next.js روی موتور Medusa

- وضعیت: پذیرفته‌شده
- تاریخ: ۱۴۰۵/۰۶/۱۰ (۲۰۲۶-۰۹-۰۱)

## زمینه

پلتفرم کلبه تا این نقطه سه پروسه جدایی داشت: دو فرانت Vite (فروشگاه روی ۵۱۷۳ و پورتال ساپلایر روی ۵۱۷۴)
و بک‌اند Medusa روی ۹۰۰۰، به‌علاوه PostgreSQL. هر پیشنمایش/استقرار به چند پورت و چند پروکسی
 CORS و پلاگین vite برای سرو کردن پنل ساپلایر از سرور فروشگاه نیاز داشت.

نیاز: «کل پروژه با یک لایه بالا بیاید — هم بک‌اند هم فرانت‌اند» بدون خروج بک‌اند از Node/TypeScript.

## تصمیم

1. **لایه Next.js 15 (App Router) در `frontend-next/` تنها درِ ورودی پروژه میشود (پورت ۳۰۰۰):**
   - فروشگاه: `app/[[...slug]]/page.tsx` — همان SPA با روتر هش‌محور، رندر کلاینت (`ssr: false`)
     چون به `window/localStorage` وابسته است. کد از `frontend-kolbe/src` کپی شده، نه بازنویسی.
   - پورتال ساپلایر: `app/supplier/page.tsx` — اپ مستقل با CSS اختصاصی خودش که فقط
     هنگام باز بودن همان صفحه تزریق و با خروج حذف میشود (بدون نشت به فروشگاه).
   - **بک‌اند:** `app/store/kolbe/[[...path]]/route.ts` و `app/admin/kolbe/[[...path]]/route.ts`
     — route handlerهایی که دقیقاً معادل پروکسی vite قبلی رفتار میکنند:
     حذف Origin/Referer، پاسخ مستقیم preflight، افزودن ACAO، و ۵۰۲ `NETWORK` وقتی موتور پایین است.
2. **موتور بک‌اند همان Medusa v2 (Node/TypeScript) میماند** — منطق تجاری، ۵ ماژول سفارشی،
   فلوفها و زرینپال دستنخورده. Next.js فقط فوروارد میکند؛ هیچ منطقی به Python یا فریمورک
   دیگری منتقل نشد و نمیشود.
3. **PostgreSQL امبدد** با باینریهای پکیج npm ‏`@embedded-postgres/linux-x64` مدیریت میشود
   (`scripts/pg.mjs`): initdb با UTF8، pg_ctl برای start/stop، ساخت دیتابیس با کلاینت pg.
   دیتای دیتابیس بیرون از ریپو (`/home/user/pg`) تا وارد git نشود.
4. **`npm run dev` کل استک را بالا میآورد** (`scripts/dev-all.mjs`):
   PostgreSQL → (در صورت تازگی) `medusa db:setup` → Medusa → seed پس از آماده شدن → Next.js.
   خرابی هر بخش فقط هشدار میدهد؛ فروشگاه مستقل از بک‌اند کار میکند.
5. **فرانتهای Vite قدیمی نگه داشته شدند** (`dev:kolbe` / `dev:supplier`) به‌عنوان میراث؛
   مسیر اصلی توسعه از این پس `frontend-next` است.

## چرا route handler و نه rewrite؟

rewrite های Next.js نمیتوانند هدر Origin درخواست را حذف کنند؛ Medusa درخواستی که
Origin مبدأ ناشناس دارد را با CORS رد میکند (مشکلی که در دوره Vite هم با پلاگین حل شده بود).
route handler کنترل کامل روی هدرها میدهد و رفتار، دقیقاً همان پروکسی قبلی است.

## چرا ssr: false برای فروشگاه؟

کل اپ روی `localStorage` (تنظیمات سایت‌ساز، تم، سبد) و `window.location.hash` بنا شده است.
SSR سمت سرور نه مقداری دارد و نه بدون بازنویسی روتر ممکن است؛ پس همان SPA داخل Next.js
سرو میشود. ارتقاء بعدی (روتر App و SSR واقعی) در رودمپ است.

## پیامدها

- یک پورت (۳۰۰۰) برای مرورگر؛ بدون CORS، بدون پلاگین vite، بدون سرو کردن خارج از root.
- بیلد production واقعی (`next build` / `next start`) در کنار `next dev`.
- `/api/health` وضعیت هر دو لایه را میدهد.
- نکته: کلید publishable دیتابیس باید با کلید hardcode فرانت یکی باشد؛ seed این را ست میکند.
