# دستورالعمل پیش‌پرواز و اجرای امن مهاجرت‌های پایگاه‌داده (Database Migration Runbook)

این سند الزامات عملیاتی، چک‌لیست پیش‌پرواز و روال‌های بازیابی از خرابی را برای مهاجرت‌های پایگاه‌داده کلبه وینتیج تعریف می‌کند.

---

## ۱. اصول حاکم بر مدیریت داده و مهاجرت‌ها

1. **فقط رو به جلو (Forward-Only DDL):**
   هیچ مهاجرت معکوس (down-migration) مجاز نیست. هرگونه اصلاح یا تغییر فاز باید از طریق افزودن مهاجرت‌های رو به جلو و سازگار با نسخه‌های قبلی (Backward-Compatible) انجام گیرد.
2. **پایداری داده و عدم DDL در زمان اجرا (No Runtime DDL):**
   تغییرات اسکیما منحصراً از طریق فایل‌های مهاجرت در `packages/database/migrations` و فرمان `npm run db:migrate` انجام می‌شود. اپلیکیشن در زمان اجرا هرگز DDL اجرا نمی‌کند.
3. **پشتیبان‌گیری پیشگیرانه (Pre-Migration Backup):**
   پیش از اجرای هرگونه مهاجرت بر روی محیط تولید، تهیه نسخه پشتیبان کامل و بررسی هش SHA-256 آن الزامی است.
4. **توقف زودهنگام در صورت ناسازگاری (Fail-Closed Startup):**
   در صورت وجود هرگونه مهاجرت اعمال‌نشده یا ناهمخوانی اسکیما، سرویس NestJS با خطای واضح بالا نمی‌آید تا از پذیرش ترافیک روی داده‌های ناسازگار جلوگیری شود.

---

## ۲. چک‌لیست گام‌به‌گام استقرار و مهاجرت

### مرحله ۱: پیش‌پرواز و ارزیابی اولیه (Preflight)
پیش از توقف یا ارتقای سرویس‌ها، وضعیت جاری پایگاه‌داده بررسی می‌شود:
```bash
node scripts/migration-preflight.mjs
```
این دستور:
- اتصال شبکه و دسترسی کاربری PostgreSQL را اعتبارسنجی می‌کند.
- تعداد مهاجرت‌های اعمال‌شده را با برنامهٔ مخزن مقایسه می‌کند.
- سلامت جدول‌ها، کلیدهای خارجی و قیود CHECK را می‌سنجد.

### مرحله ۲: تهیه پشتیبان کامل با تضمین یکپارچگی
پیش از اعمال هرگونه مهاجرت:
```bash
node scripts/backup-db.mjs --output backups/kolbe-pre-migration-$(date +%s).sql
```
این اسکریپت فایل پشتیبان و فایل اعتبارسنجی هش SHA-256 (`.sha256`) را تولید می‌کند.

### مرحله ۳: اعمال مهاجرت‌ها
```bash
npm run db:migrate
```
خروجی باید موفقیت‌آمیز بودن تمامی مراحل و عدم وجود مشکل در قیود CHECK و کلیدهای خارجی را تأیید کند.

### مرحله ۴: بازبینی پس از مهاجرت
```bash
npm run db:migrate:verify
```

### مرحله ۵: شروع به کار سرویس‌ها و تخلیه امن اتصالات
سرویس‌های بک‌اند با `npm run start` یا `docker compose up -d` راه‌اندازی می‌شوند. سرویس‌ها مجهز به Hookهای خروج امن (`app.enableShutdownHooks()`) هستند که با دریافت SIGTERM/SIGINT اتصالات باز استخر پایگاه داده را به آرامی تخلیه می‌کنند.

---

## ۳. برنامه بازیابی از خرابی (Disaster Recovery Runbook)

در صورتی که در حین مهاجرت خطایی رخ دهد:
1. **توقف فرایند استقرار:** بلافاصله جلوی انتشار نسخه‌های جدید گرفته می‌شود.
2. **بررسی لاگ‌های مهاجرت:** تراکنش Drizzle تراکنشی است؛ بنابراین در صورت بروز خطا هیچ DDL ناقصی باقی نمی‌ماند (`ROLLBACK`).
3. **بازیابی از نسخه پشتیبان در صورت لزوم:**
   ```bash
   node scripts/restore-db.mjs --input backups/kolbe-pre-migration-<timestamp>.sql
   ```
   اسکریپت ابتدا صحت هش SHA-256 را می‌سنجد تا از عدم فساد فایل پشتیبان اطمینان حاصل کند، سپس داده‌ها را بازگردانی می‌کند.
